# 과제 8 제출문 — 내 소개 페이지에 패스키 달기

- 결과물 주소: https://1-project-nine.vercel.app
- 소스 주소: https://github.com/undeadmagician32-bot/-1-
- 인증 구현 설명서(여섯 항목): [`project/docs/AUTH.md`](AUTH.md)
- 확인 기록 원문: [`project/docs/evidence-local.md`](evidence-local.md), 화면 [`project/docs/screens/`](screens/)

두 주소 모두 로그인·가입 없이 새 시크릿 창에서 열립니다. 심사하는 분은 공개 소개 페이지까지만 보시면 되고, 잠긴 자리는 열 필요가 없습니다.

## 짧은 확인 방법 (4줄)

1. **어디로 가나요**: https://1-project-nine.vercel.app 를 새 시크릿 창에서 엽니다. 아무것도 등록하지 않아도 과제 1 소개 페이지가 그대로 열립니다.
2. **세 단계 안에 무엇을 하나요**: ① 맨 위 초록 띠 "공개 영역"을 봅니다 → ② 띠의 "맨 아래 비공개 자리로 가기"를 눌러 노란 점선 경계 "여기부터 비공개"까지 내려갑니다 → ③ 새 탭에서 https://1-project-nine.vercel.app/api/private/items 를 엽니다.
3. **무엇이 보이면 통과인가요**: 위쪽에는 과제 1 의 소개(이름·강점 3개·공개 범위 점검표·결함 3개)가 그대로 보이고, 아래쪽 비공개 자리에는 "잠겨 있음"과 [패스키로 들어가기] 버튼만 보이며 메모 내용은 하나도 없습니다. ③ 의 주소는 `{"error":"패스키로 들어가야 볼 수 있습니다"}` (HTTP 401)를 돌려줍니다.
4. **안 될 때는 무엇이 보이나요**: 패스키 창을 취소하면 빨간 칸에 "패스키 선택을 취소했거나 시간이 지났습니다"가, 등록되지 않은 패스키로 시도하면 "등록되지 않은 패스키입니다"가 뜹니다. 패스키를 지원하지 않는 브라우저면 "이 브라우저는 패스키를 지원하지 않거나…"가 뜨고, 서버 설정이 빠졌으면 `/api/*` 가 `서버 설정(DATABASE_URL)이 아직 없습니다`(503)를 돌려줍니다.

## AI와 내 판단 (3줄)

1. **AI에게 맡긴 일**: 서버(등록·로그인·로그아웃·비공개 자료 API)와 비공개 자리 화면 코드 작성, SimpleWebAuthn 사용법 확인, 진짜 Chromium + 가상 인증기로 네 가지 확인을 돌려 요청·응답을 남기는 스크립트 작성, 설명서 초안.
2. **내가 직접 판단한 일**: ✏️ _(제출 전에 본인이 채우기: 예) 비공개 자리에 넣을 항목 네 가지를 정함, 패스키를 어디에 저장할지(구글 비밀번호 관리자/기기/보안 키) 고름, 마지막 패스키는 지울 수 없게 막기로 함, 과제 1 의 공개 내용은 손대지 않기로 함)_
3. **AI 말을 따르지 않은 일**: ✏️ _(제출 전에 본인이 채우기. 없었다면 왜 없었는지 — 예) "AI 가 낸 확인 기록을 직접 열어 보고 요청·응답이 맞는지 확인했고, 따르지 않을 만한 제안은 없었다" 처럼)_

## 실제 개인정보와 비밀값

- 이번에 새로 넣은 비공개 자리 내용은 모두 **만들어 넣은 것**입니다(가상 회사 "북극성랩"·"느린생각"·"열린창", 가상 메모·회고). 확인용 계정 `check-a`·`check-b` 의 메모도 가상입니다.
- 세션·질문 짝 쿠키 값은 기록에서 모두 가렸습니다. 등록 코드(`ENROLL_CODE`)와 DB 주소(`DATABASE_URL`)는 Vercel 환경변수에만 있고 저장소·기록 어디에도 없습니다. 확인 기록에 쓴 `local-test-code` 는 로컬 시험용 값으로 배포와 무관합니다.
- 공개 소개 부분의 이름·이메일 등은 과제 1 에서 공개하기로 정한 내용을 그대로 둔 것입니다(과제 8 은 1 번의 공개 내용을 유지해야 하므로 손대지 않았습니다).

## 완주 체크리스트

- [x] 공개 영역과 비공개 영역을 화면에서 갈라 두었습니다. → 맨 위 초록 띠 "공개 영역", 맨 아래 노란 점선 "여기부터 비공개" ([화면](screens/01-public-and-locked.png))
- [x] 패스키를 등록했고, 서버에 저장된 것이 공개키라는 것을 보였습니다. → [기록 "서버에 저장된 값"](evidence-local.md) (COSE 공개키, 개인키 성분 없음)
- [x] 매번 새 질문이 오고, 이미 쓴 질문은 다시 통하지 않는 것을 확인했습니다. → 등록·로그인 질문 각 3번이 모두 다름, 재사용 400
- [x] 패스키를 두 개 등록해 하나를 지운 뒤에도 들어갔습니다. → 확인용 계정에서 완료 ([화면](screens/04-two-passkeys.png)). 내 계정(`me`)은 위 "실제 기기 확인" 칸
- [x] 남의 패스키로는 열리지 않는 것을 요청과 응답으로 남겼습니다. → B-폰 서명을 A-폰 패스키로 속인 요청 401, 남의 자료 404
- [x] 제출물 어디에도 실제 개인정보와 비밀값이 없습니다.
